# BrewLog — Requirements Specification

Personal specialty coffee tracker. Log brews with a guided timer, dial in your grind with post-brew feedback, catalog beans, track equipment and roasters.

---

## 1. Domain Model

Four entities. Brew Log is central and references the other three.

### 1.1 Brew Log

A single brewing session.

| Attribute        | Type           | Description                                                          |
| ---------------- | -------------- | -------------------------------------------------------------------- |
| id               | UUID           | Unique identifier                                                    |
| date             | DateTime       | When the brew was made                                               |
| bean             | FK → Bean      | Coffee bean used                                                     |
| equipment        | FK → Equipment | Brewer used                                                          |
| grinder          | FK → Equipment | Grinder used                                                         |
| grind_setting    | String         | Grind setting as recorded on the grinder (e.g. "18 clicks", "3.5.2") |
| method           | Enum           | Pourover, espresso, immersion, cold brew, other                      |
| dose_g           | Decimal        | Coffee dose in grams                                                 |
| water_g          | Decimal        | Water weight in grams                                                |
| water_temp_c     | Integer        | Water temperature in °C                                              |
| brew_time_s      | Integer        | Total brew time in seconds                                           |
| yield_g          | Decimal?       | Output weight (espresso)                                             |
| rating           | Integer (1–5)  | Post-brew rating                                                     |
| taste_result     | Enum?          | Compass feedback: sour, bitter, watery, astringent, balanced         |
| grind_adjustment | String?        | Suggested next adjustment (e.g. "grind 2 clicks finer")              |
| tasting_notes    | Tag[]          | Flavor tags (citrus, chocolate, floral, etc.)                        |
| notes            | Text?          | Free-form notes                                                      |
| photo_url        | String?        | Optional photo                                                       |

## 2. Functional Requirements

### 2.1 Authentication

- User can register with email and password.
- User can log in and receive a session/token.
- User can log out.
- All data is private to the authenticated user.

### 2.2 Brew Timer

An interactive, Aeromatic-style guided brew timer. This is the primary entry point for creating brew logs.

**Recipe selection:**

- User can select a brew method (V60, AeroPress, Chemex, French Press, espresso, etc.) to load a default recipe with timed pour stages.
- Each recipe defines a sequence of steps. Each step has: a label (e.g. "Bloom"), a duration in seconds, a target water weight to add, and an instruction (e.g. "Pour in slow circles").
- User can customize step durations and water amounts before starting.

**Timer experience:**

- The timer shows the current step highlighted, with its label, duration countdown, and water target.
- Steps auto-advance when the timer for each step elapses. A visual and/or audio cue signals each transition.
- The next step is always previewed below the current one.
- A running total of elapsed time and total water poured is visible at all times.
- User can pause, resume, and restart the timer.
- The interface is designed to be usable one-handed on a phone.

**Post-timer flow:**

- On timer completion, the brew parameters (method, total time, total water, dose, temp) auto-populate a new brew log entry.
- The user is taken directly into the post-brew review (section 2.3).

### 2.3 Post-Brew Review & Grind Dial-In

A guided review flow after each brew. Combines subjective rating with extraction feedback that produces actionable grind adjustment suggestions (coffee compass style).

**Taste result (required):**

- User selects how the cup tastes from predefined extraction outcomes:
  - **Sour / acidic** — under-extracted. Bright, sharp, tangy, maybe salty.
  - **Bitter / harsh** — over-extracted. Dry, ashy, lingering bitterness.
  - **Watery / thin** — under-extracted and weak. Lacks body and flavor.
  - **Astringent / dry** — over-extracted. Mouth-drying, papery.
  - **Balanced** — good extraction. Sweet, clean, complex.
- Based on the taste result and the current grind setting, the app suggests a grind adjustment for the next brew using the grinder's calibration data from the equipment profile. For example: "Sour → grind 2 clicks finer on your C40" or "Bitter → grind 0.5 coarser on your Ode."
- The suggestion is saved on the brew log so the user can see their dial-in progression over time.

**Rating and tasting notes:**

- User rates the brew 1–5.
- User can select tasting note tags from a categorized flavor wheel (fruity, nutty, chocolatey, floral, spicy, sweet, etc.).
- User can add free-form notes.
- User can optionally attach a photo.

**All review data is saved as part of the brew log entry, not as a separate entity.**

### 2.4 Brew Log Management

- User can view a paginated list of brew logs showing date, bean name, method, rating, and taste result.
- User can view full details of a single brew log including the grind adjustment suggestion.
- User can edit or delete a brew log.
- User can filter brew logs by method, bean, rating, taste result, or date range.
- User can sort brew logs by date, rating, or bean name.
- User can also create a brew log manually without using the timer.

### 2.5 Coffee Bean CRUD

- User can add, view, edit, and delete beans.
- User can link a bean to an existing roaster.
- Bean detail view shows all brew logs that used this bean, giving a history of dial-in attempts for that specific coffee.

### 2.6 Equipment CRUD

- User can add, view, edit, and delete equipment.
- When adding a grinder, the user configures its grind setting format (stepped/stepless, range, unit label). This calibration data is used by the dial-in system in post-brew review.
- Equipment detail view shows all brew logs that used this piece of equipment.

### 2.7 Roaster / Café CRUD

- User can add, view, edit, and delete roasters.
- Roaster detail view shows all beans linked to this roaster.

### 2.8 Dashboard & Statistics

- Dashboard shows total brew count, average rating, and most-used brew method.
- Dashboard shows top origins and top-rated beans.
- Dashboard shows brewing frequency over time as a chart.
- Dashboard shows a dial-in summary: how many brews hit "balanced" vs. other taste results.

## 3. Non-Functional Requirements

- **Responsive design**: Must work on desktop and mobile. The brew timer must be fully usable on a phone held in one hand while brewing.
- **Performance**: Paginated lists load within 1 second for up to 1,000 records.
- **Data integrity**: Deleting a bean or equipment referenced by brew logs must warn the user and handle the dependency gracefully.
- **Usability**: The timer → review → saved log flow should feel like one seamless action. Grind dial-in suggestions should be immediately visible and actionable, not buried in data.
